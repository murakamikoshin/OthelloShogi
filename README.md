# 寝返り将棋 — NEGAERI SHOGI

**挟まれた駒は敵に寝返り、出世する。**

6×6 の盤に持ち駒を打つと、挟んだ相手の駒が裏返って自分の駒になり、同時に成る。
成った駒は新しい利きを持つので、その駒を起点にさらに挟みが成立すれば連鎖する。

## ルール

### 盤と駒

- 盤は 6×6。row 0 が後手側、row 5 が先手側。
- 駒は **玉 / 歩 / 飛 / 角** の4種。成駒は **と / 竜 / 馬**。動きは本将棋と同じ。
- 初期配置（後手は点対称）:

```
     c0  c1  c2  c3  c4  c5
r0    ・  ・ v角 v玉 v飛  ・     後手
r1    ・  ・ v歩 v歩 v歩  ・
r2    ・  ・  ・  ・  ・  ・
r3    ・  ・  ・  ・  ・  ・
r4    ・ ^歩 ^歩 ^歩  ・  ・
r5    ・ ^飛 ^玉 ^角  ・  ・     先手
```

- 持ち駒: 先手 歩4・飛1・角1 / 後手 歩3・飛1・角1
  （先手だけ歩が1枚多い。後手有利だったので付けたハンデ）

### 毎ターンできること

**A. 打つ** — 持ち駒を空マスに置く（反転が起きる）
**B. 動かす** — 盤上の自分の駒を将棋の動きで動かす（反転は起きない）

### 反転と連鎖

- **反転は「打つ」ときだけ**。打ったマスから **縦横斜めの全8方向** に挟み判定を行い、
  `相手の駒が1枚以上連続 → その先に自分の駒` が成立したら、間の駒を全部裏返す。
- **盤の端も挟みの終端になる。** 相手の駒が続いた先が盤の外なら、逃げ場を失った駒が
  まとめて寝返る。端に追い込むのが攻めの基本になる。
- 裏返った駒は持ち主が変わり、**同時に成る**（歩→と、飛→竜、角→馬）。
  すでに成駒なら成ったまま持ち主だけ変わる。
- **連鎖**: 成った駒は利きが広がるので、その新しい利きでまた挟みが成立すれば続けて裏返る。
  反転が止まるまで、最大 `MAX_CHAIN` 段まで繰り返す。
  - 同一の駒は1手番中に2回以上反転しない
  - 各段の反転は「同時解決」。処理順で結果が変わらないことをテストで保証している

### 玉

- **玉は絶対に反転しない。** 連鎖の起点にもならない。
- 相手の玉は挟みの経路を遮断する。自分の玉は挟みの終端（アンカー）になる。
- **自分の玉に隣接する駒は寝返らない。** 玉のまわりが安定地帯になる
  （これが無いと守り駒が一手で全部寝返り、序盤で一方的に玉を取られる）。

### その他

- 移動による成りは無い。成る手段は反転だけ。打つときは常に不成。
- 移動で取った駒は持ち駒になる（成駒は不成に戻る）。玉を取ったら勝ち。
- 二歩は無し。歩は最終段に打てない・動けない。
- 王手放置は合法。詰み判定はしない。
- 合法手が無ければパス。両者が連続でパスしたら盤上の駒数が多い方の勝ち（同数は引き分け）。
- 同一局面が4回出現したら盤上の駒数で決着。
- 持ち時間は各3分、1手ごとに5秒加算（オンライン対戦のみ）。

## 棋譜の書き方

座標は必ず **row → col** の順。どちらも 0〜5。

| 書き方 | 意味 |
|---|---|
| `P*13` | 歩を row1 col3 に打つ（P=歩 R=飛 B=角。どちらの駒かは手番で決まる） |
| `42-32` | row4 col2 の駒を row3 col2 に動かす |
| `pass` | パス（合法手が1つも無いときだけ） |

`#` 以降は行コメント。`kifu/` に例があります。

## バランス調整で変える前提の数値（`src/core/rules.ts`）

| 定数 | 既定値 | 意味 |
|---|---|---|
| `BOARD_SIZE` | 6 | 盤の一辺。変えれば初期配置も棋譜表記も追従する |
| `INITIAL_SETUP` | 玉/飛/角+歩3 | 初期配置（先手ぶん。後手は点対称） |
| `INITIAL_HANDS` | 先手 歩4飛1角1 / 後手 歩3飛1角1 | 初期持ち駒 |
| `FLIP_DIRECTION_MODE` | `'all8'` | 挟み判定の方向。`'attack'`（利きのみ）/ `'wide'`（利き＋縦横）/ `'all8'` |
| `KING_GUARDS_NEIGHBORS` | `true` | 玉に隣接する駒は寝返らないか |
| `WALL_ANCHORS` | `true` | 盤の端を挟みの終端として認めるか |
| `PROMOTE_DROP_AT` | 0 | 打った駒自身が成るのに必要な反転枚数（0 で無効） |
| `PLY_LIMIT` | 0 | この手数で決着しなければ駒数判定（0 で無制限） |
| `MAX_CHAIN` | 5 | 1手番の連鎖の段数上限 |
| `SLIDE_FLIP_RANGE` | 無制限 | 飛・角・竜・馬の走る方向の挟み判定の距離 |
| `STEP_FLIP_RANGE` | 無制限 | 歩・と金など1マスだけ利く方向の挟み判定の距離 |

### 調整の経緯（AI 同士の対局で測った）

| 段階 | 反転が起きた打ち手 | 平均手数 | 先手勝率 |
|---|---|---|---|
| 当初（利きの方向のみ・空の盤） | 2% | 16手 | 71% |
| 全8方向にした | 8% | — | — |
| 初期配置を陣形にした | — | 29手 | — |
| 玉の隣を守るようにした | 42% | 51手 | 33% |
| 先手に歩1枚のハンデ | 42% | 61手 | 47% |
| **盤の端をアンカーにした** | **81%** | 53手 | 59% |

最後の変更がいちばん効いた。各案を40局ずつ比べた結果:

| 案 | 1手の反転枚数 | 3連鎖以上が出た対局 | リード交代 |
|---|---|---|---|
| 変更前 | 0.76 | 15% | 7.0 |
| **盤の端をアンカーに** | **2.51** | **85%** | 7.4 |
| ＋打った駒も出世 | 3.06 | 80% | 9.9 |
| 打った駒も出世だけ | 0.72 | 13% | 5.0 |
| 連鎖上限を3に | 0.71 | 8% | 5.8 |
| 60手で駒数決着 | 0.69 | 3% | 4.8 |

「打った駒も出世」を足すと反転がさらに増えるが、リード交代が 9.9回まで上がって
毎手ひっくり返る展開になり、将棋側の戦略性が薄れるので入れていない。
`PROMOTE_DROP_AT = 3` にすればいつでも試せる。

### いまの数字（AI 同士 100局・深さ3）

| | |
|---|---|
| 平均手数 | 52.7 |
| 盤の埋まり率 | 61% |
| 打つ手のうち反転が起きる割合 | 81% |
| 1手あたりの反転枚数 | 3.08 |
| 3連鎖以上が出た対局 | 87% |
| 4連鎖以上が出た対局 | 38% |
| リード交代の平均回数 | 10.4 |
| 一度もリードが入れ替わらない対局 | 0% |
| 負けた側も一度はリードしていた対局 | 98% |
| 勝負が決まった時点 | 81% 地点 |
| 先手勝率 | 59% |

盤の色が何度も入れ替わり、最後までもつれる。それでいて運ゲーにはなっておらず、
**深さ3 の AI は深さ2 の AI に24局中20勝**する（先後どちらでも）。
決着の98%は玉取りなので、オセロ側は手段・将棋側が目的、という関係も保たれている。

先手のハンデは歩1枚。無しだと先手勝率 40%、歩1枚だと 59%。
駒は1枚単位でしか動かせないので、将棋やチェスと同じく
「先手がわずかに有利」の側に倒してある。

自分で測り直すには:

```bash
npm run report -- 100 3   # 100局回して数字を出す
npm run sweep -- 40 3     # ルールの候補を並べて比べる
```

## 実装の方針

- **ルール判定は `/src/core` だけに書く。** クライアントとサーバが同じコードを使うので、
  盤面が食い違うことがない。サーバは受け取った手を必ずここで検証し、
  クライアントの申告する局面・時間・勝敗は一切信用しない。
- `/src/core` は DOM も fetch も Worker API も参照しない。
- ライブラリは最小限。UI フレームワーク・状態管理・ORM は入れていない。
